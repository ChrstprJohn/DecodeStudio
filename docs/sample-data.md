# Sample data for design

Run from the repository root in PowerShell 7:

```powershell
./scripts/Seed-SampleData.ps1
```

The script uses the existing local portfolio connection in .NET User Secrets and
the installed ASP.NET Core 10 password hasher. No package installation or database
schema change is required. Content lives in scripts/seed/sample-data.json.

## What it adds

| Table | Samples |
| --- | --- |
| SiteContent | One studio record with hero, About, contact, and footer copy |
| Projects | Eight published fictional website concepts |
| Services | Eight published studio services |
| TeamMembers | Eight published fictional team members, including one sample owner |
| SocialLinks | Eight demo links pointing to example.com |
| Users | Eight demo User accounts: six active, two inactive |

SiteContent remains a singleton; eight studio records would not match the app's
schema. The sample team owner is website content, not an admin login account.

The script generates 17 local SVG placeholders: one hero, eight website previews,
and eight initials-based team avatars. These are demo graphics, not real project
screenshots or staff photos. Files are saved under wwwroot/uploads/images and
served locally without external image services. Use the admin file pickers to
replace them with PNG/JPEG/WebP images when designing.

Demo image filenames are stable and shared with demo profiles. They are retained
when replacing/deleting individual records so other demo records can still use
them. Missing demo assets are regenerated when the script runs again. Uploaded
real image filenames still use the normal replacement/deletion cleanup behavior.

## Existing data and reruns

- The script inserts only missing sample records, using project/service title,
  team first+last name, social-link label, and account email as matching keys.
- Existing matching rows, publication choices, roles, and passwords are preserved.
- Existing nonempty studio fields remain unchanged; blank/null studio fields are
  filled with sample values.
- Existing admin accounts are not edited or promoted.
- Database writes run in a transaction and sample/image presence is checked
  before commit. Repeated runs do not add duplicates for unchanged sample keys.
- Renaming a sample record changes its matching key; a future seed run may add
  the original named sample again. There is no destructive reset operation.

## Generated service artwork

Eight generated WebP service illustrations live in `MyPortfolio/wwwroot/images/services/`. Each matching sample in `scripts/seed/sample-data.json` now has an `ImagePath` value. `scripts/Set-ServiceSampleImages.ps1` backfills these values for existing sample records, preserving uploaded images. It has been applied locally. Replace an image through Admin → Services → Edit; the file picker appears directly beneath the description and shows the current image.

Exact built-in image-generation prompts and source image paths are recorded in `scripts/seed/service-image-assets.json`. The former SVG placeholder images and their generator were removed after verifying no database references.

## Image locations

- `MyPortfolio/wwwroot/images/services/` holds the service card illustrations.
- `MyPortfolio/wwwroot/images/projects/` holds the portfolio thumbnails. Files beginning with `preview-` are design concepts. The named screenshots show the live projects.
- `MyPortfolio/wwwroot/uploads/images/` holds uploaded images and the demo SVGs generated by the seed script.
- `scripts/seed/sample-data.json` maps the service and project entries to their image URLs.
